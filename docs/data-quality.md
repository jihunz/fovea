# 데이터 품질 검사

Overview의 **Data quality** 카드는 모델 없이 찾을 수 있는 데이터 문제를 보여 준다: 근중복과 분할 간 누수, 라벨이 서로 다른 쌍둥이 이미지, 시퀀스 안의 라벨 불일치, 클래스에 비해 이상한 박스 모양, 흐리거나 어둡거나 과노출된 이미지. 이 문서는 각 플래그가 무엇을 뜻하고 어떻게 계산되며 어디서 오탐이 나는지 정리한다. 기본 임계값은 실제 넘어짐 검출 데이터셋 VFP290K(7,808 프레임, 168개 영상, 고정·손에 든 카메라)에서 맞췄다. 구현: `src/fovea/core/qa.py`.

라벨 파일 자체의 문제(형식 오류 등)와 AI 라벨 감사 결과도 같은 `issue=` 필터로 다루므로 뒤쪽에 함께 정리했다.

## 언제 실행되나

- **인덱싱 직후 자동**: 데이터셋을 등록하거나 다시 인덱싱하면(경로 이동 포함) 검사 잡이 이어서 돈다. 인덱싱이 진행 중이면 카드에 *Indexing is running — the checks start by themselves when it finishes*가 보인다.
- **증분**: 파일이 바뀐(mtime) 이미지만 다시 해시한다. 연결이 끊긴 드라이브의 이미지는 *읽을 수 없음*으로 기록하지 않고 다음에 다시 시도한다.
- **라벨을 고치면 몇 초 안에 다시 검사**: 편집기 저장, 일괄 라벨 작업, Objects 편집, 스냅샷 되돌리기, AI 쓰기, 제안 수락이 끝나면 그 이미지들을 모아 **마지막 저장 3초 뒤(첫 저장 후 최대 15초)** 라벨 기반 검사만 다시 돌린다. 잡도 배너도 만들지 않으며, 카드 머리에 *updating after your edits…*가 잠시 보인다. 다시 검사하는 범위:
  - 편집한 이미지가 속한 (분할, 시퀀스)의 모든 프레임 → `seq_*`
  - 편집한 이미지와 그 근중복 쌍둥이(쌍둥이의 쌍둥이까지 문맥으로) → `dup_label_mismatch`
  - 데이터셋 전체 박스의 모양 통계를 다시 계산 → `shape_outlier` (박스 60만 개 초과면 저장된 통계로 채점하고 0.5% 이상 변하면 전체 재계산)
  
  편집이 3,000장을 넘거나(numpy 없으면 200장), 데이터셋의 4분의 1을 넘거나(400장 이상인 데이터셋), 영향 범위가 3만 프레임을 넘으면 대신 일반 검사 잡 하나(*Rechecking edited labels*)를 큐에 넣는다. 증분 결과는 전체 재실행과 같다(테스트로 확인). Annotate는 저장 약 3.6초 뒤 그 이미지의 플래그 칩과 filmstrip 표시를 제자리에서 갱신한다.
- **읽을 때 확인**: 요약을 열었을 때 결과가 없거나, 새 이미지가 있거나, 검사 뒤 라벨이 바뀌었으면 백그라운드 실행을 큐에 넣는다(데이터셋당 30초에 한 번).
- **수동**: 카드의 **Check again** / **Run checks**, 또는 `POST /api/datasets/<id>/qa {"checks": [...]}`(`duplicates`, `sequence`, `shape`, `quality`, `labels`).

이미지 픽셀에서 나오는 플래그(근중복, 누수, 흐림·어두움·과노출)는 라벨 편집으로 바뀌지 않으므로 다시 인덱싱해 파일이 바뀌었을 때만 다시 계산된다.

**어디서 계산하나**: 검사는 순수 Python 계산이라 서버 안에서 돌리면 GIL을 잡고 있어 다른 요청이 기다린다(측정: 검사 중 Explore 100행 페이지가 6 ms → 1 s). 그래서 이미지가 **2,000장 이상**인 데이터셋은 인덱스를 읽기만 하는 짧은 자식 프로세스(`python -c`)에서 계산하고, 해시와 플래그를 DB에 쓰는 일만 서버가 한다(7,808장에서 실행 중 요청 지연 150 ms → 2 ms). 편집 후 재검사도 데이터셋이 2,000장 이상이고 다시 볼 범위(시퀀스 프레임 + 근중복 쌍둥이)가 2,000프레임 이상이면 같은 방식이다. 더 작은 검사는 프로세스 시작 비용(약 0.15초)이 더 커서 서버 안에서 계산한다. 자식 프로세스를 띄울 수 없는 환경이면 경고를 로그에 남기고 서버 안에서 계산한다. 인덱스 폴더에서 파일 잠금이 프로세스 사이에 공유되지 않을 때도 마찬가지다(macOS Docker Desktop의 바인드 마운트 `./data:/app/data`): 그런 폴더에서는 자식 프로세스가 SQLite 연결을 닫으면서 서버의 `-wal`·`-shm`을 지워, 이후 요청이 `disk I/O error`로 실패한다. 그래서 첫 자식 프로세스 전에 한 번, 서버가 열어 둔 시험용 DB를 자식 프로세스가 열고 닫은 뒤에도 WAL이 남는지 확인한다. 자식 프로세스는 연결을 닫지 않고 끝난다. 취소하면 자식 프로세스도 끝난다.

## 해시와 이미지 통계

이미지마다 한 번, 긴 변 320 px 이하로 디코딩해서(JPEG은 DCT 축소, EXIF 회전 반영, 16비트 대응) 다음을 저장한다.

- **64비트 dHash** — 장면의 큰 구조. 같은 카메라 시점인지 판단할 때 쓴다. 고정 카메라에서는 연속 프레임의 67%가 3비트 이내라서, 이것만으로 근중복을 판정하면 영상 대부분이 중복이 된다.
- **256비트 dHash**(17×16) — 사람 한 명이 움직인 것도 보인다. API의 모든 `dist`는 이 해시의 해밍 거리다: **0 동일, ≤ 2 근중복, 약 35 같은 카메라의 다른 순간, > 64 무관**.
- 평균 밝기(luma 0–255), 대비, 선명도(1 − Crete-Roffet blur effect, 클수록 선명). 라플라시안 분산은 야간 프레임을 모두 흐리다고 판정해서 쓰지 않았다.

모든 쌍 비교는 비둘기집 원리의 밴드 분할(LSH)로 하므로 임계값 안의 쌍을 빠짐없이 찾으면서 빠르다. 같은 해시를 가진 이미지(완전 복사본, 검은 프레임)는 하나의 노드로 접는다.

## 플래그

| 코드 | 화면 이름 | 뜻 |
| --- | --- | --- |
| `near_dup` | Near-duplicate image | 거의 같은 사진이 데이터셋 안에 또 있음 |
| `leak_split` | Duplicate across splits | 거의 같은 사진(또는 같은 장면의 프레임)이 다른 분할 역할(train/val/test)에 있음 — 누수 |
| `dup_same_role` | Same frame in two folders of one split | 거의 같은 사진이 같은 분할 역할의 다른 폴더에 있음 — 누수가 아닌 정보 |
| `dup_label_mismatch` | Duplicates labeled differently | 거의 같은 사진인데 라벨이 다름 |
| `seq_gap` | Box missing in one frame of a sequence | 앞뒤 프레임에 있는 물체의 박스가 이 프레임에만 없음 |
| `seq_flicker` | Class flickers in a sequence | 같은 물체의 클래스가 1–2프레임 동안만 바뀜 |
| `seq_jump` | Box jumps in a sequence | 가만히 있는 물체의 박스가 한 프레임에서만 튐 |
| `seq_count_spike` | Box count spike in a sequence | 박스 수가 한 프레임에서만 급증·급감 |
| `shape_outlier` | Unusual box shape for its class | 클래스 안에서 종횡비나 면적이 극단적 |
| `blurry` | Blurry image | 비슷한 밝기의 이미지보다 유난히 흐림 |
| `dark` | Dark image | 절대적으로도, 이 데이터셋 기준으로도 어두움 |
| `overexposed` | Overexposed image | 절대적으로도, 이 데이터셋 기준으로도 밝음 |

### 근중복 · 누수 · 라벨 불일치 (`duplicates`)

누수는 폴더 이름이 아니라 **분할 역할**로 판단한다. 역할은 Export가 폴더를 `data.yaml`의 train/val/test에 매핑하는 규칙과 같다: `train`·`val`·`test`와 그 별칭(`training`, `valid`, `validation`, `eval`, `dev`, `testing`)은 그대로, 다른 이름은 첫 단어로(`test-1854-1860-포함` → test), 나머지는 train. 그래서 같은 영상이 `test`와 `test-1854-1860-포함`에 함께 있어도 평가 프레임이 학습에 들어간 것이 아니므로 누수가 아니다. Overview 카드, Explore 필터, `DATASET_CARD.md`가 모두 이 기준으로 센다.

- **`near_dup`**: 256비트 거리 ≤ `dup_dist`(2)인 이미지를 묶는다. 묶음은 *리더 중심* 군집이라 모든 구성원이 리더와 2비트 이내다(체인처럼 이어 붙이면 천천히 변하는 영상 전체가 한 덩어리가 된다). 큰 그룹부터 번호를 매기고, 크기·해시·픽셀 통계까지 같은 것은 *exact* 복사본으로 표시한다. 검사는 그룹만 저장하고, 내보내기가 남길 1장(*keep*)은 `GET /api/datasets/<id>/qa/duplicates`를 읽을 때 정한다: 승인 > 라벨 있음 > 박스 많음 > 먼저 인덱싱된 것(이미지 ID가 작은 것). Export의 **Drop near-duplicate images**와 같은 규칙이고(내보내기는 그룹 중 선택에 든 이미지 안에서 고른다), 리뷰나 라벨을 바꾸면 바로 반영된다.
- **`leak_split`**: 다른 분할 역할의 폴더에 거리 ≤ `leak_dist`(6)인 쌍둥이가 있으면 *twin*. 또 시퀀스(`seq`) 하나의 프레임이 둘 이상의 분할 역할에 들어가 있고 역할이 다른 프레임끼리 같은 카메라 시점(64비트 거리 ≤ `scene_dist` 8)이면 *seq* 사유로 표시한다. 이름만 같은 시퀀스(예: 휴대폰 사진 `IMG_xxxx`)는 목록에만 올리고 표시하지 않는다.
- **`dup_same_role`**: 같은 역할의 다른 폴더(예: `test`와 `test-1854-1860-포함`)에 거리 ≤ `leak_dist`인 쌍둥이가 있음. 그 분할에서 같은 프레임이 두 번 세어질 뿐 누수는 아니므로 정보로만 표시한다. 내보내기 전에 정리하려면 **Drop near-duplicate images**를 쓴다.
- **여러 분할에 걸친 시퀀스**: 프레임이 둘 이상의 분할 역할에 들어간 시퀀스를 카드 아래 *Sequences in more than one split*에 시퀀스, 폴더별 프레임 수, 같은 시점 증거와 함께 보여 준다. 같은 역할의 두 폴더에만 걸친 시퀀스는 나열하지 않는다. 같은 영상이 학습과 평가에 함께 있으면 검증 점수가 부풀려진다. Export → **Make new train / val / test splits**가 시퀀스 단위로 나눠 준다.
- **`dup_label_mismatch`**: 거리 ≤ 2인 라벨된 이미지 쌍의 라벨을 비교한다. 박스 수가 다르면 *count*, 클래스 구성이 다르면 *class*, 같은 클래스끼리 IoU ≥ `mismatch_iou`(0.5)로 1:1 짝이 안 맞으면 *boxes*. 여러 장이 거의 같으면 다수와 다른 *튀는 쪽*만 표시하고, 동점이면 양쪽 모두 표시한다.
- 오탐과 한계: dHash는 멀리 있는 몇 픽셀짜리 차이를 보지 못한다. 그래서 고정 카메라에서 작은 사람만 다른 두 프레임은 근중복이 된다(VFP290K train+val의 14%). 그런 쌍에서 라벨이 다르면 `dup_label_mismatch`가 잡아 준다.

### 시퀀스 (`sequence`)

- **시퀀스 찾기**: 이미지를 (분할, `seq`)로 묶고 파일 이름 자연 정렬(`_9` 다음 `_10`)로 나열한다. 연속 프레임의 64비트 거리 중앙값이 `seq_video`(12)를 넘으면 영상이 아니라 사진 모음으로 보고 검사하지 않는다. 연속 프레임 거리가 `seq_cut`(20)을 넘으면 장면이 바뀐 것으로 보고 그 자리에서 자른다. 라벨된 프레임만 쓰므로 아직 라벨하지 않은 프레임은 오류가 아니다. 3프레임 이상인 장면만 검사한다.
- **연결**: 이웃 프레임의 박스를 헝가리안 알고리즘으로 짝짓는다(비용 = 1 − IoU + 대각선 대비 중심 거리 + 클래스가 다르면 0.5; 겹치거나 중심이 대각선의 0.75배 이내이고 크기가 3배 이내일 때만 후보).
- **`seq_gap`**: 앞·뒤 프레임에서 같은 클래스로 이어지는 물체가 있는데, 이 프레임에는 그 물체의 박스가 없음. 짝짓기는 1:1이다: 이웃 프레임의 박스와 이어진 이 프레임의 박스는 그 물체의 것이라 다른 물체를 설명하지 못하고, 어느 이웃과도 이어지지 않은 박스는 예상 위치 근처(같은 클래스, IoU ≥ 0.1 또는 중심이 예상 박스 대각선의 0.75배 이내)에 있을 때 빠진 물체 **하나**만 설명한다. 그래서 가까이 붙은 두 물체 중 하나만 라벨되어 있어도 잡는다. 예상 박스가 함께 저장된다.
- **`seq_jump`**: 앞·뒤 프레임에서 같은 클래스·IoU ≥ 0.5로 거의 그대로인 물체가, 이 프레임에서만 예상 박스와 IoU < 0.3이고 실제로 크게 움직였거나(중심이 예상 박스 대각선의 절반과 8 px 중 큰 값 이상 이동 — 작은 박스는 8 px, 큰 박스는 대각선의 절반이 기준) 면적이 2.25배 넘게 달라짐.
- **`seq_flicker`**: 연결 사슬에서 양쪽 클래스가 같은데 1–2프레임만 다른 클래스.
- **`seq_count_spike`**: 이 프레임의 박스 수가 앞·뒤 모두보다 많거나 모두보다 적고, 차이가 2개와 이웃 박스 수의 25% 중 큰 값 이상.
- 오탐: 연결은 클래스를 가리지 않으므로 박스가 다른 물체 가까이 지나가면 가짜 `seq_flicker`가 나올 수 있다(표본 5개 중 1개).

### 박스 모양 (`shape`)

- **`shape_outlier`**: 클래스마다 로그 종횡비(픽셀 기준)와 로그 면적의 강건 z 점수(중앙값과 MAD)를 계산해 |z| ≥ `shape_z`(5.0)인 박스를 표시한다. 박스가 `shape_min`(30)개 미만인 클래스는 판정하지 않는다. 이미지 가장자리에 잘린 박스는 종횡비가 임의적이라 종횡비 점수와 통계에서 빼고 면적만 본다(VFP290K에서 종횡비 이상치 대부분이 화면 밖으로 반쯤 나간 사람이었다). z 4.0은 VFP290K의 4%를 표시해 5.0으로 올렸다.

### 이미지 품질 (`quality`)

- **`dark`**: 평균 밝기 < `dark_floor`(25) **그리고** 데이터셋 강건 z ≤ −`dark_z`(−2.5). 둘 다 요구하므로 전체가 어두운 CCTV 데이터셋을 통째로 표시하지 않는다(z만 쓰면 VFP290K의 18%가 표시됐다).
- **`overexposed`**: 평균 밝기 > `bright_floor`(215) 그리고 z ≥ `bright_z`(2.5).
- **`blurry`**: blur effect ≥ `blur_floor`(0.30) 그리고 **비슷한 밝기 구간 안에서** z ≥ `blur_z`(4.2). 야간 프레임은 원래 부드러워서(중앙값 0.29 대 낮 0.21) 전체 기준 하나로는 선명한 야간 프레임을 표시하고 흐린 주간 프레임을 놓쳤다. 대비가 거의 없는 프레임(검은 화면, 렌즈 캡)은 판정하지 않는다. 오탐 경계: 표시된 것과 아닌 것의 차이가 작다(오탐은 z 3.9–4.1 근처). 데이터셋에 맞게 조정하려면 아래 임계값을 바꾼다.

## 결과 쓰기

- Overview 카드의 **Review** → Explore `?issue=<code>&sort=flag&order=desc`. 여러 코드를 쉼표로 묶을 수 있고 `issue=any`는 라벨 파일 문제나 품질 플래그가 하나라도 있는 이미지다.
- **가장 의심스러운 것부터**: 플래그마다 점수가 있고(`image_flags.score`), *Most suspicious first* 정렬(`sort=flag`)은 `issue=`가 고른 플래그 중 가장 높은 점수 순이다. 점수는 근중복·누수는 쌍둥이와 가까울수록, `dup_label_mismatch`는 *class* > *count* > *boxes*, `seq_gap`·`seq_jump`는 빠지거나 튄 박스가 많을수록, `seq_flicker`는 1프레임만 바뀐 쪽, `seq_count_spike`는 차이가 클수록, `shape_outlier`·`blurry`·`dark`·`overexposed`는 z가 클수록 높다. 서로 다른 플래그의 점수는 비교할 수 없으므로 이 정렬은 `issue=`가 품질 플래그를 고를 때만 메뉴에 나온다. 정렬을 고르지 않으면 Explore와 Annotate 모두 플래그로 거른 목록을 이 순서로 연다(라벨 파일 문제와 `issue=any`는 점수가 없어 Index 순). 직접 고른 정렬은 URL에 남는다.
- Explore 타일의 이슈 점, Inspect의 플래그 칩과 **Similar images**(256비트 거리 순 12장, 다른 분할이면 표시), `GET /api/datasets/<id>/images/<iid>/qa`(예: 공백의 예상 박스, 튄 행, 쌍둥이 이미지 ID).
- Annotate의 플래그 칩과 filmstrip `!` 표시. `seq_gap`의 경우 `POST /api/datasets/<id>/images/<iid>/fill-gap`이 앞뒤로 가장 가까운, 박스가 있는 프레임 두 장에 `seq_gap`과 같은 규칙을 적용해, 그 두 프레임에서 같은 클래스로 이어지는 물체 중 이 프레임에 박스가 없는 것의 예상 박스를 보간 제안으로 만든다(플래그가 알린 것을 그대로 채움). 위치는 파일 이름의 프레임 번호로 가중한다(번호가 없으면 가운데). 같은 클래스끼리만 잇는다: 클래스가 바뀌는 물체(넘어짐)까지 잇는 것은 `K` 보간이다. UI에서는 Annotate의 플래그 칩 옆 **Fill from neighbours** 버튼이다: 한 번 클릭하면 보간 제안(≈, *Filled from <앞 프레임> and <뒤 프레임>*)이 생기고 `Enter`로 수락, `⇧Enter`로 모두 수락한다. 여러 프레임을 한꺼번에 채울 때는 `K`로 키프레임 두 개를 표시하고 **Interpolate**.
- Export의 **Drop near-duplicate images**(그룹마다 승인 > 라벨 있음 > 박스 많음 > 먼저 인덱싱된 것 순으로 1장)와 시퀀스 단위 분할 빌더. `DATASET_CARD.md`의 *Data quality* 절에 근중복·누수·분할에 걸친 시퀀스·기타 플래그 수가 들어간다. 카드도 Overview처럼 누수와 걸친 시퀀스를 분할 역할로 세되, 그 내보내기가 실제로 쓰는 분할(새 분할 빌더 포함) 기준이다.
- Explore 필터의 숫자는 다른 활성 필터를 모두 적용한 개수다. 예를 들어 `split=train`에서 *Near-duplicate image* 옆 숫자는 train 안의 근중복 수다.

## 임계값 바꾸기

데이터셋마다 덮어쓸 수 있다. 아직 UI는 없고 API로 바꾼다. 바꾼 임계값이 영향을 주는 검사만 다시 돈다(품질 임계값만 바꾸면 다시 해시하지 않는다).

```bash
B=http://localhost:8000/api/datasets/<dataset-id>
curl -s $B/qa/settings                                    # 현재 값, 기본값, 덮어쓴 값, 필드 설명과 범위
curl -s -X PUT -H 'content-type: application/json' \
     -d '{"options": {"blur_z": 3.5, "dark_floor": 40}}' $B/qa/settings     # 저장하고 해당 검사 재실행
curl -s -X PUT -H 'content-type: application/json' \
     -d '{"reset": true}' $B/qa/settings                  # 기본값으로 (또는 "reset": ["blur_z"])
```

`"rerun": false`를 붙이면 저장만 한다. 범위를 벗어난 값은 400.

| 키 | 기본값 | 범위 | 뜻 |
| --- | --- | --- | --- |
| `dup_dist` | 2 | 0–16 | 근중복·라벨 불일치로 볼 256비트 거리 |
| `leak_dist` | 6 | 0–24 | 다른 폴더의 쌍둥이(`leak_split`, `dup_same_role`)로 볼 256비트 거리 |
| `scene_dist` | 8 | 0–24 | 분할에 걸친 시퀀스에서 "같은 카메라 시점"으로 볼 64비트 거리 |
| `mismatch_iou` | 0.5 | 0.1–0.95 | 쌍둥이 이미지의 박스가 일치한다고 볼 IoU |
| `seq_cut` | 20 | 4–64 | 새 장면으로 자를 연속 프레임 64비트 거리 |
| `seq_video` | 12 | 2–40 | 영상으로 볼 연속 프레임 거리 중앙값의 상한 |
| `shape_z` | 5.0 | 2–20 | 박스 모양 이상치 z (낮을수록 많이 표시) |
| `shape_min` | 30 | 5– | 모양을 판정할 클래스의 최소 박스 수 |
| `blur_floor` | 0.30 | 0–0.9 | 흐림으로 볼 최소 blur effect |
| `blur_z` | 4.2 | 1–20 | 같은 밝기 구간 안에서의 흐림 z |

| `bright_floor` / `bright_z` | 215 / 2.5 | 128–255 / 0–20 | 과노출: 평균 밝기 하한 / z |

## 라벨 파일 문제 (Health check)

인덱싱 때 라벨 파서가 기록한다. Overview의 *Label issues* 타일과 Health check에 나온다.

| 코드 | 화면 이름 | 기준 |
| --- | --- | --- |
| `missing_label` | No label file | 라벨 파일 없음. 아직 라벨하지 않았다는 뜻이므로 문제 수에는 넣지 않는다(정보) |
| `empty_label` | Empty label file | 박스 없는 라벨 파일(의도한 배경일 수 있음) |
| `bad_format` | Malformed line | 값이 5개 미만이거나 숫자가 아님(nan/inf 포함), 정수가 아닌 클래스 ID(`1.7`) |
| `bad_class` | Invalid class id | 음수이거나 클래스 목록 밖 |
| `out_of_range` | Box outside image | 박스가 0–1 범위를 0.005 넘게 벗어남 |
| `zero_area` | Zero-area box | 너비나 높이 ≤ 0 |
| `tiny_box` | Tiny box (< 0.01% area) | 정규화 면적 < 0.0001 |
| `duplicate_box` | Duplicate box | 같은 클래스 박스끼리 IoU > 0.95 |
| `image_unreadable` | Image unreadable | 이미지를 열 수 없음 |

클래스 상태도 함께 본다: 박스가 하나도 없는 클래스, 박스 수가 클래스별 박스 수 중앙값(박스가 있는 클래스만 셈)의 10% 미만인 클래스, 라벨된 분할 중 어딘가에 없는 클래스, 클래스 목록에 없는 ID.
